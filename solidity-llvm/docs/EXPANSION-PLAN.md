## Приоритет 1 — MCP-сервер SCSA  ⬅ KEYSTONE, реализуется первым

**Зачем (деньги + ограничение).** У нас нет бюджета на API-токены — есть только подписочный Claude Code.
MCP-обёртка делает `sca` вызываемым инструментом для подписочного Claude → **нейро-символическая петля
работает за $0 API**: Claude выдвигает гипотезу → зовёт sca-tool → получает символьный/форк-вердикт →
уточняет. Тренд 2025 (Anthropic SCONE-bench, Cyfrin Aderyn MCP): инструмент должен быть вызываемым агентом.

**Архитектура (AD-5!).** Сервер — ТОНКАЯ обёртка: только зовёт бинарь `sca` и парсит его вывод.
Ноль логики анализа в сервере. Каталог `~/diplom/mcp/`.

**Реализация.** Python stdlib-only (без pip-зависимостей — как AD-1/AD-2 «ноль зависимостей»),
JSON-RPC 2.0 по stdio (newline-delimited). Файл `mcp/scsa_mcp.py`.

**Tools (тонкие обёртки над CLI):**
| tool | CLI под капотом | отдаёт |
|---|---|---|
| `sca_audit` | `--input\|--address --audit --json` | находки, отсортированы по priorityScore |
| `sca_context_pack` | `--llm-context` | markdown-сенсор (IR-факты+гипотезы) — вход в петлю |
| `sca_poc` | `--poc [--victim --fork-block]` | Foundry-PoC (форк = истина) |
| `sca_invariant` | `--emit-invariant --invariant-property` | forge stateful-харнесс |
| `sca_target_value` | RPC `eth_getBalance` (+ERC20) | on-chain ценность цели (деньги-приоритизация, П.2) |

Регистрация: `.mcp.json` → сервер `scsa`. Env `SCA_BIN` (путь к бинарю), `SCSA_RPC_URL[_<chain>]`.

**Готово когда:** из Claude Code `sca_audit` на fixture возвращает те же находки, что CLI; `sca_context_pack`
отдаёт пак; петля hunt проходит без единого API-вызова.

## Приоритет 2 — Приоритизация по деньгам (on-chain TVL)  ⬅ деньги-прямо

**Зачем.** Вывод Anthropic SCONE-bench: **ценность эксплойта коррелирует с активами контракта, а не со
сложностью бага.** Значит хантить надо там, где лежат деньги. `scoreFinding` ([Driver.cpp:296]) сейчас даёт
ТОЛЬКО внутренний вес класса — он не знает, сколько на контракте лежит.

**Решение (не в C++, а в оркестрации — AD-5).** TVL — это триаж/сеть, не анализ. Живёт в MCP-слое:
`sca_target_value(address, chain)` тянет `eth_getBalance` + балансы известных токенов через public-RPC
(env `SCSA_RPC_URL_<chain>`; деградирует до "unknown" без ключа). MCP-tool `sca_audit` при наличии адреса
домножает финальный приоритет на log(value). Батч `hunt_batch.sh` может сортировать очередь по value×score.

**Готово когда:** `sca_target_value` на известном адресе возвращает баланс; очередь хантинга ранжируется
value×severity, дорогие цели наверху.

## Приоритет 3 — CI / editor режим (аудитория = команды-разработчики)

**Зачем.** Расширяет с хантеров на команды (ориентир — Aderyn/Slither в CI). Не прямые деньги баунти,
но канал распространения и «вторая нога» продукта.

**Что уже есть:** `--sarif` (SARIF 2.1.0 для GitHub code-scanning) — половина сделана.

**Чего не хватает (реализация — следом за П.1/П.2):**
1. `--markdown` репортер (`report/MarkdownReporter.cpp`) — как Aderyn: находки в markdown-таблице,
   для PR-комментов/README. Регистрация флага в `main.cpp` + `Driver.cpp`.
2. `ci/` — готовый GitHub Action (`action.yml`) + pre-commit hook, зовущие `sca --audit --sarif`,
   exit 2 при HIGH → красный CI. Тонкая обёртка над бинарём.
3. Fast-режим: `--audit` уже быстрый (docker solc — узкое место); опция `--no-solc-cache`/локальный solc — future.

**Готово когда:** `sca --audit --markdown` даёт таблицу; GitHub Action роняет CI на HIGH-находке демо-репо.

## Приоритет 4 — Hard-set датасеты для метрик  ⬅ ДИПЛОМ, реализация отложена

**Зачем.** Честный раздел валидации диплома. Zhang et al. (516 реальных уязвимостей, инструменты покрывают
~20.5% — arxiv 2312.16533) + DAppSCAN (arxiv 2305.08456) как «hard set»: видно, где SCSA в тех 20.5%, где нет.

**Реализация (ОТЛОЖЕНА — не деньги):**
1. `benchmarks/hardset/` — загрузчик DAppSCAN + подмножества Zhang-516 (скрипт скачивания, нормализация
   в наш формат `expected.json`).
2. `run_hardset.sh` — прогон `sca --audit` пачкой, P/R/F1 против разметки, отчёт в `RESULTS.md`.
3. Честная таблица «класс бага → символика бьёт / LLM-слой нужен / вне досягаемости».

**Готово когда:** есть P/R по классам на hard-set; в дипломе — таблица покрытия vs 20.5% baseline.
