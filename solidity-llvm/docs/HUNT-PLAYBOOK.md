# HUNT-PLAYBOOK — методичка нейро-символического баг-хантинга

> Как Claude Code (аналитик) работает вместе с SCSA (сенсор+доказатель), чтобы находить
> оплачиваемые баги. Читается slash-командой `/hunt`. Это не «поиск паттернов» — детекторы
> уже отработали в контекст-паке. Задача аналитика — **логика/экономика**, которую статика
> не видит, с обязательным подтверждением.

## 0. Железное правило

**Ни одна гипотеза не становится находкой без подтверждения.** Три уровня доказательства
(в порядке силы): нарушенный инвариант (forge/medusa) → символьный путь (KLEE) → рабочий
PoC (forge test на форке). Неподтверждённое — это «кандидат», так и помечаем. Это лекарство
от главной болезни LLM-аудиторов: правдоподобные, но ложные находки (lexical bias).

## 1. Воронка (где мы экономим лимиты)

```
Stage 0  benchmarks/hunt_batch.sh (--dir | --addrs) — sca --audit пачкой. Дёшево. Без Claude.
         → hunt_queue.md: выжившие (есть HIGH) отсортированы для разбора.
Stage 1  sca --llm-context — контекст-пак на выжившего кандидата (факты из IR). Дёшево.
Stage 2  Claude читает пак + этот плейбук → РАНЖИРОВАННЫЕ гипотезы. ← мы здесь дорогие
Stage 3  Claude драйвит доказательство: инвариант (--emit-invariant) / KLEE / PoC через
         sca+forge+docker (verify_invariant.sh, verify_poc.sh).
Stage 4  Подтверждено → отчёт по шаблону §4. Не подтверждено → выкинули, идём дальше.
```

Claude включается только на Stage 2+ и только по контракту, где Stage 0/1 дали зацепку или
подозрительную форму. Широкий скан тысяч контрактов — детерминированный `sca` без Claude.

## 2. Как читать контекст-пак

- **Зацепки детекторов** — уже подтверждённые паттерны (reentrancy/AC/oracle). Отработай их
  первыми: для HIGH сразу проверь возможность PoC.
- **Факты по функциям** — это ground truth. `auth=да` значит гвард РЕАЛЬНО в IR (модификатор
  заинлайнен solc). `ext>0` — уходит управление наружу. `$in=да` — принимает ether. `map[]` —
  per-user балансы. Не переспоряй факты пересказом текста — верь IR.
- **Карта storage** — кто пишет/читает каждый слот. Скаляр, который пишут несколько функций,
  но проверяет только часть — классическая дыра доступа.
- **Гипотезы** — хуки под категории ниже. Это стартовые нити, не приговор.
- **Рекомендованные инварианты** — если SCSA распознал форму (ERC4626/payable-vault), он сразу даёт
  готовую команду `verify_invariant.sh <src> <prop>`. Гоняй её первой — forge доказывает/опровергает
  за минуты, без ручного написания харнесса.

## 3. Чеклист категорий (сигнал в паке → ручная проверка → чем подтвердить)

### 3.1 Access control (ставка #1, $953M)
- **Сигнал:** функция пишет *скалярный* слот, `auth=нет`, не `internal`. Или инициализатор
  без гварда; роль/owner, меняемая несколькими путями.
- **Проверь:** намеренно ли публично? может ли не-owner вызвать? `initialize()` без защиты от
  повторного вызова? спутаны ли роли (admin vs operator)?
- **Подтверди:** KLEE `--klee-mode access-control` (оракул: `priv_written ∧ msg.sender≠owner`)
  → PoC `--poc` (атакующий `vm.prank` вызывает привилегированную функцию).

### 3.2 Reentrancy / CEI
- **Сигнал:** `ext>0` И пишет storage; общий слот у нескольких публичных функций (cross-fn);
  чтение слота, обновляемого после внешнего вызова (read-only reentrancy).
- **Проверь:** порядок checks-effects-interactions; можно ли из callback повторно войти в ЭТУ
  или ДРУГУЮ функцию, читающую тот же слот до обновления.
- **Подтверди:** KLEE `--klee-mode reentrancy` (форк глубины 1) → PoC с реентрантным `receive()`.

### 3.3 Price / oracle manipulation (топ-оплачиваемый)
- **Сигнал:** `oracle-spot` в фактах; цена/курс из `getReserves`/баланса пула.
- **Проверь:** spot vs TWAP/Chainlink; можно ли флеш-займом сдвинуть цену в пределах блока;
  используется ли эта цена для минта/займа/ликвидации.
- **Подтверди:** инвариант «цена не двигается за 1 tx больше X» ломается фаззером; PoC с
  флеш-займом на форке.

### 3.4 Accounting / vault (rounding, share-inflation — Balancer/Cetus 2025)
- **Сигнал:** `$in=да` + `map[]` (держит ether и балансы); функции deposit/mint/withdraw/redeem.
- **Проверь:** инвариант `Σ balances == address(this).balance` (или totalSupply×price);
  first-depositor может ли раздуть share ценой (donate → скачок `pricePerShare`); в чью
  пользу округляет `convertToShares/Assets` (должно — против пользователя во ВСЕХ путях).
- **Подтверди:** три готовых свойства (`verify_invariant.sh <file> <prop>`, реально гоняет `forge test`):
  `solvency` (no-overdraw, по reentrancy/vault-находке); `inflation` (first-depositor, ETH-payable форма
  `deposit() payable`+`redeem(uint256)`); `inflation-erc20` (**реальный ERC4626** над ERC20 — inline
  MockERC20/approve/transferFrom, форма `constructor(address)`+`deposit(uint256)`+`redeem(uint256)`).
  и `roundtrip` (**округление**: `convertToAssets(convertToShares(x))<=x` — ловит rounding-creates-value,
  класс Balancer-2025; форма `constructor(address)`+`deposit`+`convertToShares/Assets`).
  Сломанный инвариант = подтверждённый баг с контрпримером. Демо: `benchmarks/invariant_demo/`
  (`*_vuln`→СЛОМАН, `*_safe`→держит). Для своего свойства (monotonic supply и т.п.) — допиши
  инвариант в сгенерированный харнесс. **Это классы, которые платят и которые детекторы не видят.**

### 3.5 Input validation (34.6% контрактных эксплойтов)
- **Сигнал:** `address`-параметр, идущий в privileged-запись или в target внешнего вызова;
  отсутствие `require` (мало `require×N`).
- **Проверь:** zero-address, границы сумм, whitelist target; unchecked возврат ERC20
  (`transfer` не проверен) — `unchecked-call` в зацепках.
- **Подтверди:** PoC с граничным входом; для unchecked-return — токен, возвращающий false.

### 3.6 Delegatecall / storage collision / upgradeability
- **Сигнал:** `kind=delegatecall`; прокси-паттерн.
- **Проверь:** совпадает ли layout implementation и proxy; можно ли подсунуть свой target;
  не затирается ли слот 0 (owner/impl).
- **Подтверди:** PoC перезаписи слота через delegatecall (SWC-112).

### 3.7 Прочее (ручной обзор, слабый автосигнал)
- **DoS:** внешний вызов/push в цикле, unbounded-массив → griefing.
- **Signature/replay:** `ecrecover` без проверки `!=address(0)`, отсутствие nonce/chainid.
- **MEV/slippage:** отсутствие `minOut`/`deadline` в свопах.
- **Token integration:** fee-on-transfer/rebasing ломают учёт «до/после».

## 4. Шаблон подтверждённой находки (для сабмита)

```
[SEVERITY] <класс> в <контракт>.<функция> (строка N)
Корень: <одно предложение — что именно нарушено>
Инвариант/свойство, которое ломается: <формула>
Подтверждение: <KLEE witness | forge invariant counterexample | forge test PASS>
PoC: <путь к .t.sol>, воспроизведение: forge test ...
Влияние: <что крадётся/ломается, оценка $>
Фикс: <короткая рекомендация>
```

## 5. Границы честности

- Не заявляем «полностью автономный аудитор» — это human-in-the-loop (Claude триггерит человек).
- Off-chain (ключи, supply-chain, фишинг) — вне охвата, не притворяемся (Bybit $1.5B не наш класс).
- Если гипотеза не подтвердилась — так и пишем, не «возможно уязвимо» без доказательства.
- Логические баги, требующие понимания намерения протокола (спека), — граница: помечаем как
  «требует ручного суждения», не выдаём за доказанное.
