# HUNT-LOOP-PLAN — автономный нейро-символический хант-цикл

> Как SCSA-петля работает САМА, итеративно, через `/loop`. Оркестрирует уже существующую
> инфру (`hunt_feeder.sh` → `hunt_batch.sh` → `/hunt`-методология → `--emit-invariant`/`--poc` →
> `forge`), а Claude (подписка) = аналитик-в-петле на дорогом шаге. Ноль API-токенов.
>
> **Читать вместе с:** `HUNT-PLAYBOOK.md` (методология разбора одной цели — железное правило,
> чеклист категорий, шаблон находки). Этот файл — про АВТОМАТИЗАЦИЮ и СОСТОЯНИЕ поверх плейбука.

---

## 0. Что делает цикл (одна фраза)

Каждая итерация: **берёт следующую свежую цель → дешёвый триаж `sca` → если выжила, глубокий
разбор + подтверждение forge-PoC на форке → подтверждённое кладёт в findings и алертит, остальное
честно скипает → двигается дальше.** Состояние переживает итерации (не переразбираем то же).

## 1. Почему цикл, а не один прогон

Реальный recall тула на аудированном коде ≈ 0 (ROADMAP), деньги — на СВЕЖИХ мелких протоколах.
Значит хант = **поток**: много целей, дешёвый фильтр отсекает 95%, дорогой анализ идёт только по
выжившим. Цикл автоматизирует поток; человек подключается только когда цикл нашёл **подтверждённого**
кандидата. Это funnel, не «кнопка денег»: честное ожидание — большинство итераций = SKIP/CLEAN.

## 2. Стадии одной итерации

```
S0. ПОПОЛНЕНИЕ (если очередь пуста/коротка)
    источник целей (по приоритету доступности):
      (a) hunt/queue.md уже не пуст → сразу к S2
      (b) **АВТОПОИСК КОНТЕСТОВ (главный источник свежих оплачиваемых целей):**
          find_targets.py → hunt/contests.md + targets.json (активные Sherlock/Cantina контесты:
          репо+scope+приз+KYC). Выбрать топ БЕЗ-KYC (доступнее с РФ) → fetch_scope.py <#|title>
          (in-scope .sol) → fetch_deps.py <#|title> (submodule-зависимости OZ/solmate/safe —
          БЕЗ них solc не компилит; транзитивное замыкание) → hunt_batch.sh --dir hunt/repos/<contest>.
          Контест-код СВЕЖИЙ и платит → EV тула тут положителен (в отличие от mainnet-аудированного).
      (c) hunt/seed.txt (адреса, что дал человек: конкретные контракты) → hunt_batch.sh --addrs
      (d) hunt_feeder.sh (нужны RPC_URL+ETHERSCAN_API_KEY) → свежие верифиц. 0.8-адреса → hunt_batch.sh
    hunt_batch.sh строит hunt/queue.md: выжившие (есть HIGH/MEDIUM) с приоритетом.
    **Скоуп контеста строгий:** сверяйся с _scope.txt (in-scope пути) и правилами контеста —
    out-of-scope классы/severity-модель у каждого свои.

S1. ВЫБОР следующей НЕобработанной цели из hunt/queue.md (сверяясь с hunt/processed.txt).
    Приоритет = priorityScore × on-chain ценность (sca_target_value). Дорогие цели первыми.

S2. ГЛУБОКИЙ РАЗБОР (Claude = аналитик, дорогой шаг):
    - sca --llm-context (или mcp sca_context_pack) → контекст-пак.
    - Пройти чеклист §3 HUNT-PLAYBOOK. Заземляться на факты IR, не на пересказ.
    - Ранжировать гипотезы деньги×достижимость×уверенность; отбросить опровергнутые фактами.

S3. ПОДТВЕРЖДЕНИЕ (железное правило — без него НЕ находка):
    - accounting/vault/rounding → sca --emit-invariant → verify_invariant.sh → forge test.
    - reentrancy/access-control → --emit-klee (кандидат) → --poc → forge на форке (ИСТИНА).
    - Форк реального EVM = финальная истина (позиция A: KLEE=эвристика, forge-green=доказательство).
    - Нет средства подтвердить сейчас (нет RPC) → кандидат помечается «unconfirmed + чем подтвердить».

S4. ВЫХОД:
    - forge-green подтверждение → hunt/findings/<addr>.md по шаблону §4 плейбука + АЛЕРТ человеку.
    - иначе → строка в hunt/log.md (skip/clean/unconfirmed + причина).
    - в ЛЮБОМ случае: адрес → hunt/processed.txt (не переразбираем).

S5. ПАУЗА до следующей итерации (см. §5 каденс).
```

## 3. Состояние (файлы в `~/diplom/hunt/`)

| Файл | Роль |
|---|---|
| `seed.txt` | входные адреса от человека: `0xADDR[,chain]` по строке (свежие цели). Комментарии `#`. |
| `queue.md` | очередь выживших после `hunt_batch.sh` (есть HIGH/MEDIUM), с приоритетом. |
| `processed.txt` | адреса, УЖЕ разобранные (любой исход) — защита от повторной работы. |
| `findings/<addr>.md` | ПОДТВЕРЖДЁННЫЕ находки (forge-green), по шаблону §4 плейбука. |
| `log.md` | журнал итераций: цель → исход (clean/skip/unconfirmed/CONFIRMED) + причина. |

Инвариант состояния: **цель обрабатывается ровно один раз** (S1 всегда сверяется с `processed.txt`).

## 4. Границы честности (не нарушать — иначе шум вместо денег)

- **Нет forge-green → не находка.** «Правдоподобно» ≠ баг. Помечаем unconfirmed, не алертим.
- **Скоуп программы важнее находки.** Прежде чем алертить — проверить, что класс IN-scope у этой
  программы (trusted-роли/market-risk/rounding-без-потерь на зрелых протоколах обычно OUT). Если
  цель — из баунти-программы, свериться с её правилами.
- **Не выдавать неподтверждённое за доказанное** в findings.
- **Не хантить то, что вне досягаемости тула** (logic/intent на зрелом коде, oracle-манипуляция без
  модели рынка) — цикл их пометит CLEAN, это ОК, не додумывать баг.
- **Дубликаты аудитов = $0.** Если цель уже дважды-аудирована — понизить приоритет (деньги на свежем).

## 5. Каденс и остановка

- **Самопейс** (`/loop` без интервала): после каждой итерации планировать следующее пробуждение;
  задержку выбирать по тому, чего ждём (пополнение фидером — долго; разбор — сразу к следующему).
- Если очередь и seed пусты И фидер недоступен (нет ключей) → длинная пауза + записать в log
  «нет целей, жду seed». Не крутить вхолостую.
- **Стоп-условия:** (1) **ЖЁСТКОЕ ОКОНЧАНИЕ В 19:00** — в начале каждой итерации проверяй текущее
  время (`date +%H:%M`); если уже ≥ 19:00 — НЕ начинай итерацию, запиши в log.md «стоп: 19:00»,
  останови цикл (не планируй пробуждение); (2) человек остановил; (3) N итераций подряд без цели.
  Планируя следующее пробуждение — не назначай его позже 19:00.
- Подтверждённая находка → НЕ останавливаться (до 19:00), но АЛЕРТ обязателен (человек решает по сабмиту).

## 6. Требования окружения

- `docker` (solc + forge) — обязателен для компиляции и forge-подтверждения.
- Фетч: `ETHERSCAN_API_KEY` опционален (есть Sourcify-фолбэк + `--explorer-url` для L2/L3).
- `hunt_feeder.sh`: нужны `RPC_URL` + `ETHERSCAN_API_KEY`. Нет их → работаем от `seed.txt`.
- Форк-подтверждение PoC/инвариантов на живой жертве: нужен `RPC_URL` целевой сети.

## 7. Промпт для `/loop`

Запуск (самопейс): `/loop` + текст ниже. Или с интервалом: `/loop 30m <текст>`.

```
Ты — аналитик в автономном хант-цикле SCSA. Следуй solidity-llvm/docs/HUNT-LOOP-PLAN.md
и HUNT-PLAYBOOK.md буквально. Выполни РОВНО ОДНУ итерацию за вызов, поддерживая состояние
в ~/diplom/hunt/.

0. СТОП В 19:00: сначала проверь время (`date +%H:%M`). Если уже ≥ 19:00 — не начинай итерацию,
   запиши в hunt/log.md «стоп: 19:00», останови цикл (не планируй пробуждение), заверши.
1. Состояние: создай ~/diplom/hunt/ если нет (queue.md, processed.txt, log.md, findings/, seed.txt).
2. S0 Пополнение: если в queue.md нет НЕобработанных целей (сверь с processed.txt) —
   (главное) benchmarks/find_targets.py → активные Sherlock/Cantina контесты (hunt/contests.md);
   выбери топ БЕЗ-KYC → benchmarks/fetch_scope.py <#|title> → hunt_batch.sh --dir hunt/repos/<contest>.
   Иначе seed.txt → hunt_batch.sh --addrs; либо hunt_feeder.sh при RPC_URL+ETHERSCAN_API_KEY.
   Если целей нет вообще — log.md «нет целей», длинная пауза, заверши итерацию.
3. S1 Выбор: возьми ОДНУ необработанную цель с наивысшим приоритетом (priorityScore × ценность
   через sca_target_value, если есть сеть).
4. S2 Разбор: sca_context_pack (MCP) или sca --llm-context; пройди чеклист HUNT-PLAYBOOK §3,
   заземляясь на факты IR; ранжируй гипотезы, отбрось опровергнутые.
5. S3 Подтверждение (железное правило): для топ-гипотезы гони forge-доказательство
   (--emit-invariant→verify_invariant.sh, или --poc→forge на форке). Форк реального EVM = истина.
   Нет средства подтвердить → кандидат «unconfirmed + чем подтвердить».
6. S4 Выход: forge-green → hunt/findings/<addr>.md (шаблон §4 плейбука) + ЯВНЫЙ АЛЕРТ мне в ответе.
   Иначе → строка в hunt/log.md. В любом случае адрес → processed.txt.
7. Проверь скоуп программы (§4 плана) ПЕРЕД алертом. Не выдавай неподтверждённое за находку.
8. Кратко отчитайся: что за цель, исход, что дальше. Запланируй следующее пробуждение по §5,
   но НЕ позже 19:00 (в 19:00 цикл заканчивается).

Границы: без forge-green — не находка; не хантить logic/intent на зрелом аудированном коде
(помечай CLEAN, не додумывай); дубликаты аудитов = низкий приоритет. Ноль API-токенов — весь
LLM-анализ это ты (подписка).
```

## 8. Первый запуск — чеклист человека

1. Положи свежие цели в `~/diplom/hunt/seed.txt` (адреса из новых листингов/баунти-программ,
   формат `0xADDR[,chain]`). БЕЗ них цикл нечем кормить (кроме фидера с ключами).
2. Убедись: `docker` жив; для форк-подтверждения — `export RPC_URL=...` целевой сети.
3. Запусти `/loop` с промптом §7. Следи за `hunt/log.md` и алертами.
4. Пришёл алерт (forge-green) → открой `hunt/findings/<addr>.md`, проверь скоуп программы, сабмить.
