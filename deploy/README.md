# Деплой витрины SCSA на свой VPS

Закрытый (basic-auth) сайт: React-фронт + Go-бэкенд + анализатор `sca`.
Всё поднимается двумя контейнерами: **backend** (API+статика) и **caddy** (HTTPS+гейт).

## Что нужно на сервере
- Linux VPS с **Docker** и **Docker Compose v2** (≈ 2 CPU / 4 GB / 20 GB — минимум).
- Домен, чья A-запись указывает на IP сервера (для авто-HTTPS).
- Ключ Etherscan (для скана по адресу).

## Как устроено (важно понимать)
Бинарь `sca` компилирует Solidity через `docker run ethereum/solc:…`. Контейнеру
бэкенда монтируется **docker-сокет хоста**, и solc-контейнеры запускаются на демоне
ХОСТА. Поэтому:
- нужные образы solc тянутся на **хост** (первый скан новой версии — медленнее);
- монтирование сокета = **root-эквивалент** на хосте → доступ закрыт basic-auth’ом.

## Шаги

**1. Установить Docker (если нет)**
```bash
curl -fsSL https://get.docker.com | sh
```

**2. Скопировать репозиторий на сервер** (git clone / scp / rsync).

**3. Настроить окружение**
```bash
cd deploy
cp stack.env.example stack.env
# сгенерировать хэш пароля для входа:
docker run --rm caddy:2 caddy hash-password --plaintext 'ПРИДУМАЙ_ПАРОЛЬ'
# впиши в stack.env: DOMAIN, ETHERSCAN_API_KEY, BASIC_AUTH_USER, BASIC_AUTH_HASH
nano stack.env
```

**4. (рекомендуется) Предзагрузить образы solc на хост** — чтобы первый скан не ждал:
```bash
for v in 0.8.19 0.8.20 0.8.24 0.8.28; do docker pull ethereum/solc:$v; done
```

**5. Собрать и запустить**
```bash
docker compose up -d --build      # первая сборка ~5–15 мин (LLVM + фронт)
docker compose logs -f backend    # смотрим старт
```

**6. Проверить**
```bash
curl -u admin:ПАРОЛЬ https://ВАШ_ДОМЕН/api/health     # → {"ok":true,...}
```
Открыть `https://ВАШ_ДОМЕН` → браузер спросит логин/пароль → витрина.

## Обновление
```bash
git pull && docker compose up -d --build
```

## Диагностика
- **502 / бэкенд не стартует** → `docker compose logs backend`. Часто: не смонтирован
  docker.sock или у контейнера нет прав на него.
- **скан по адресу падает** → пустой `ETHERSCAN_API_KEY` в `stack.env`.
- **скан долгий/таймаут** → образ solc тянется впервые; предзагрузи (шаг 4) или подними `SCAN_TIMEOUT`.
- **HTTPS не выпускается** → домен не указывает на сервер, или закрыты порты 80/443.
- **Caddy ругается на `basic_auth`** → старая версия; в Caddyfile заменить на `basicauth`.

## Безопасность (коротко)
Доступ закрыт basic-auth’ом (единственный гейт). Внутри: без шелл-инъекций, таймаут на
скан, лимит на размер исходника, лимиты CPU/памяти на контейнер. Компиляция чужого кода
уходит в одноразовый solc-контейнер. docker.sock — доверенная граница: держи доступ закрытым.
Для полностью публичного режима нужны rate-limit и, лучше, изоляция сокета (rootless/sysbox).
